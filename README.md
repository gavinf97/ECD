# ECD

Tooling for the **ELIXIR Community Database (ECD)**, following the
[ECD Process V1](https://doi.org/10.5281/zenodo.17288943) and the
[ECD Checklist V1](https://doi.org/10.5281/zenodo.17289009).

### Where the results are deposited

All results live on the **[`uptime-data`](https://github.com/gavinf97/ECD/tree/uptime-data)
branch** — never on `main`. The checks commit once an hour, and keeping them off `main` stops
that traffic from burying the code history. The branch is also the GitHub Pages source, so each
push republishes the dashboard.

```
branch uptime-data
├── index.html      the dashboard, served at gavinf97.github.io/ECD
├── STATUS.md       the status page, rendered by GitHub
├── summary.json    current status of every resource, machine-readable
├── history.json    per-resource daily uptime, last 90 days
├── state.json      current state per resource: since, consecutive downs, last code
├── events.jsonl    append-only audit trail of every state change
├── badges/*.json   shields.io endpoints behind the badges above
└── daily/YYYY/YYYY-MM-DD.json    daily counters and latency histogram per resource
```

Everything there is regenerated by
[`uptime/scripts/summarize.py`](uptime/scripts/summarize.py) after every check, and squashed
to one commit per UTC day. Raw per-check rows are not kept, so the branch grows by about
10 MB a year.

Monitoring is continuous and has no end date. 99% — the ECD health-check target in
[ECD Process V1](https://doi.org/10.5281/zenodo.17288943) §5 — is reported as a reference
line, not as a deadline: nothing starts a clock and nothing expires.

## Components

Two independent components. Each has its own folder, dependencies, tests and README, and
neither imports from the other.

| Folder | Component | What it does |
|---|---|---|
| [`uptime/`](uptime/) | **ECD uptime tracker** | Checks 163 ELIXIR data resources every hour with GitHub Actions and publishes their uptime. **[Dashboard →](https://gavinf97.github.io/ECD/)** |
| [`agent/`](agent/) | **ECD Agent Skill** | A Claude Agent Skill that takes a resource's name and URL, pre-fills the ECD Checklist with evidence, and renders it as JSON, Markdown, DOCX, PDF and HTML. |

## Repository layout

```
agent/                     ECD Agent Skill (SKILL.md, scripts/, references/, templates/, tests/, examples/)
uptime/                    uptime tracker
  resources.yml            the 163 monitored resources — the list that is checked
  scripts/                 check.py (runs the checks), summarize.py (builds every report)
  dashboard/index.html     the dashboard, published to the uptime-data branch each run
.github/workflows/
  uptime-check.yml         hourly checks; commits results to uptime-data
  uptime-tests.yml         uptime/ tests, run on changes to uptime/**
branch uptime-data         all results (see above). Never merged into main.
```

`main` holds the code for both components; the tracker only ever writes to `uptime-data`.

## Install the agent skill

```bash
ln -s "$(pwd)/agent" ~/.claude/skills/ecd-agent-skill
pip install -r agent/requirements.txt
```

For usage, see [`agent/README.md`](agent/README.md). For the tracker — what is monitored, how a
resource is judged up or down, and how to add or fix one — see [`uptime/README.md`](uptime/README.md).
